## Additional verification before publication

- The modal keyboard-containment check passed separately on all three engines (3/3, no retries): Tab and Shift+Tab remain within the revocation dialog, and cancel restores focus. This is supplementary coverage, not three more unique scenarios added to the 23-test matrix.
- Axe left `color-contrast` incomplete for text over the decorative gradient and `aria-hidden-focus` incomplete for the modal background. The rendered mobile background was sampled with content hidden: its brightest sampled color was RGB (20, 14, 32), giving contrast ratios of 7.36:1 for muted text, 18.07:1 for foreground text and 10.22:1 for accent text. This measurement and the keyboard check address those manual-review prompts without suppressing scanner rules or claiming full accessibility conformance.
- The editor placeholder's reduced opacity was removed after the first local matrix; corrective commit `67ba9c0` and merge `bbf4518` subsequently rebuilt and passed all 52 unit/integration tests and 24 browser scenarios in Linux CI. The live synthetic script also passed against deployed Worker `3e3695d2-1b36-42df-b204-cc0e79668a4b`.

## Language selection at startup

On the November 14 frontend, the WebKit iPhone profile accepted a selection of Vietnamese while the editor was still loading. Once the client started, the selection reverted to English. The regression check failed against that build because the server-rendered selector was enabled. The fix uses TanStack Router's hydration state to enable the selector when it can apply the user's choice. A clean build also exposed Nitro deriving its compatibility date from the calendar. Pinning the frontend to November 14 restored startup with the locked `workerd`.

All 24 local browser scenarios passed with the fix. The first Linux PR job timed out while downloading Ubuntu packages for Playwright. The second attempt ran all tests on the same commit and passed, as did the run on the merged source. [PR #3](https://github.com/sovergarden-dev/cryptoscroll/pull/3) · [PR CI, attempt 2](https://github.com/sovergarden-dev/cryptoscroll/actions/runs/44708493896/attempts/2) · [Main CI](https://github.com/sovergarden-dev/cryptoscroll/actions/runs/44711406531)

After publication, both mobile profiles found the selector disabled in the initial HTML and successfully switched the interactive site to Vietnamese. The first QR run reached its 18-second click timeout in the WebKit recipient. Cleanup verified HTTP 410 for its fixture. The repeat run kept the same timeout and completed both directions, including a wrong passphrase, a correct read, clearing the display and reopening the destroyed link. Both repeat fixtures also returned 410. The first timeout's cause was undetermined.

## Firefox scanner regression and tooling pin

The first full matrix passed 20/21 scenarios. Firefox repeatedly reported `frame.evaluate: Page crashed` when axe analyzed the styled application. It also reproduced in an isolated run, legacy axe mode, disjoint rule groups, with CSP bypassed in a diagnostic context, and with the previous axe-core 4.13.0. A minimal plain-HTML fixture passed. No native crash cause has been established; do not attribute this to a specific browser/CSP/CSS defect without more evidence.

The first Linux CI run at `1293b2e` reproduced the same failure: [run 43582679479](https://github.com/sovergarden-dev/cryptoscroll/actions/runs/43582679479) passed 23 browser scenarios and failed only the Firefox audit. Earlier head `bf18c0d` also failed. No merge or deployment followed those failures.

Further controls isolated ARIA label references, not styles or heading text. A minimal unchanged page crashed when a role lookup preceded axe, but passed with a CSS-only lookup. This matches [Mozilla bug 2090055](https://bugzilla.mozilla.org/show_bug.cgi?id=2090055) and [Playwright regression 43967](https://github.com/microsoft/playwright/issues/43967): the browser crashes when two JavaScript worlds read the same reflected ARIA element list. CSS-only interactions were insufficient for the full multi-state audit. Experimental product label changes and harness workarounds were discarded.

Playwright is pinned to its last-working stable 1.64.1. Version 1.65.1 still packages Firefox revision 1572, so that patch release does not provide a fixed browser. The original production ARIA references, semantic locators, rule set, CSP, timeouts and assertions remain intact. Explicit region/dialog name assertions were added, and Firefox audits are enabled on Windows as well as Linux. The unchanged seven-state Firefox audit passed locally with 1.64.1 and subsequently passed Linux CI at `67ba9c0` ([run 43589377381](https://github.com/sovergarden-dev/cryptoscroll/actions/runs/43589377381)) and `bbf4518` ([run 43589898896](https://github.com/sovergarden-dev/cryptoscroll/actions/runs/43589898896)). Upgrade the pin only after a release carrying the upstream fix passes the same audit and functional matrix. Real TalkBack/VoiceOver acceptance remains open.

Original failure evidence is retained locally in `.local-qa/followup-first-firefox-crash/` and `.local-qa/followup-firefox-diagnostic.log`; further diagnostic fixtures are ignored under `.local-qa/`. The final matrix is recorded separately from the initial failure.
